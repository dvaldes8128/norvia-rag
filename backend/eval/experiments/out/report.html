Norvia retrieval validation

Offline A/B of the hybrid retrieval pipeline (dense + lexical fuse, same weights as production) on InsuranceQA-v2 — the closest well-known public retrieval corpus to insurance / policy Q&A — using the two Ollama embedding models already pulled locally.

Generated 2026-11-03 20:05:44Z Corpus: 250 answers Queries: 100 Near-copy gate: 0.0 (off) Hybrid weights: vector 0.6 / text 0.4 Embed window: 512 chars Ollama: cpu
Headline. embeddinggemma wins on this InsuranceQA slice: dense nDCG@10 0.936 (Acc@1 0.89) vs nomic-embed-text dense 0.847 (Acc@1 0.76). Hybrid (0.6/0.4) does not beat dense top-1 here — it slightly hurts Acc@1 on both models; only nomic gains a little coverage at @10. Practical takeaway for Norvia open QA: prefer embeddinggemma for the vector channel and keep near-copy at 0 (or low) unless the UX is quote-matching.

Protocol

  • Dataset: deccan-ai/insuranceQA-v2 test split (Feng et al. InsuranceQA).
  • Slice: 100 random unique questions; corpus = all their gold answers + random negatives → 250 passages (CPU-friendly; relative model comparison).
  • Gold = answers written for that exact question text.
  • Dense: cosine on L2-normalised Ollama embeddings with model task prefixes.
  • Hybrid: Norvia fuse_scores over dense ∪ BM25 candidate pools (stand-in for pgvector + FTS).
  • This run is an experiment harness — not the CI pytest suite.
